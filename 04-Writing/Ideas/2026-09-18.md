# 2. The Data Engineer's New Security Boundary: Agent Identity

This is the **most architecturally interesting** topic on the list.

The agent ecosystem is moving beyond “give the model an API key.” Recent research is exploring verifiable agent identity and delegation across MCP and A2A, including capability-based authorization and provenance. ([arXiv](https://arxiv.org/abs/2603.24775 "AIP: Agent Identity Protocol for Verifiable Delegation Across MCP and A2A"))

The Linux Foundation also launched the first vendor-neutral MCP certification on September 14, covering architecture, interactions, security/governance and ecosystem. That's a useful signal that MCP is becoming a genuine engineering/platform discipline. ([Linux Foundation](https://www.linuxfoundation.org/press/agentic-ai-foundation-launches-mcpa-certification-to-validate-mcp-expertise "Agentic AI Foundation Launches MCPA Certification to Validate MCP Expertise"))

### Working title

**Who Is the Agent? Identity and Authorization in the MCP Era**

### Core question

Traditional API security asks:

> “Who is the user?”

Agent systems increasingly need to answer:

> “Which agent, acting on whose behalf, with which authority, using which tools, is performing this action?”

# 4. MCP Compatibility Is Becoming a Security Problem

Here's a genuinely niche topic.

Research published this year has identified **clause-compliance vulnerabilities** in MCP implementations: because compatibility requirements can leave some protocol behaviors optional, different SDK implementations can behave differently in ways that create attack surfaces. ([arXiv](https://arxiv.org/abs/2603.10163 "Compatibility at a Cost: Systematic Discovery and Exploitation of MCP Clause-Compliance Vulnerabilities"))

Another security framework analyzes MCP through multiple attack surfaces and argues for defense-in-depth mechanisms such as capability-based access control, tool attestation and runtime policy enforcement. ([arXiv](https://arxiv.org/abs/2604.05969 "A Formal Security Framework for MCP-Based AI Agents: Threat Taxonomy, Verification Models, and Defense Mechanisms"))

### Working title

**The MCP Specification Is Not Your Security Boundary**

### Outline

# 6. Your AI Agent Should Not Have a Database Password

A deliberately opinionated companion to #2.

### Working title

**Stop Giving AI Agents Database Credentials**

Instead of saying “agents need secure access,” make the argument that **database credentials are the wrong abstraction altogether**.

### Compare

**Bad**

```text
Agent
  ↓
DB credentials
  ↓
SELECT / UPDATE / DELETE
```

**Better**

```text
Agent
  ↓
Governed Tool
  ↓
Policy
  ↓
Semantic Operation
  ↓
Database
```

For example:

```text
get_customer_revenue(customer_id)
```

instead of:

```sql
SELECT *
FROM customers
JOIN orders ...
```
