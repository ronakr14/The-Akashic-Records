## 1. MCP Just Became Infrastructure: What the 2026-07-28 Spec Means for Data Engineers

**My #1 pick this week.**

MCP's July 28, 2026 specification is a substantial architectural change, not just another feature release. The protocol core is now stateless, requests can be routed through ordinary load balancers, tool catalogs become cacheable, authorization was hardened, and Tasks/MCP Apps moved into the extensions model. [Model Context Protocol Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/?utm_source=chatgpt.com)

That gives you something much better to write about than “What is MCP?”

### Possible title

**MCP Is Becoming Infrastructure: What Data Engineers Need to Know About the 2026 Specification**

### Outline

1. MCP's original problem
2. Why stateful MCP was awkward to operate
3. The new stateless architecture
4. What changed operationally
    - Load balancing
    - Caching
    - Routing
    - Authorization
5. Tasks and long-running data operations
6. MCP + databases + warehouses
7. What this means for Data Platform architecture
8. What I would build differently today
9. Production checklist

### Practical project

Build a tiny:

`LLM → MCP Client → MCP Server → PostgreSQL`

Then deploy multiple MCP server instances behind a normal HTTP load balancer and demonstrate why statelessness matters.

### Effort

**5–7 hours**

# 2. The Data Engineer's MCP Stack: From Database Access to Agent-Ready Data Platforms

This is the more ambitious follow-up.

Instead of explaining MCP itself, ask:

> **If agents are going to interact with data platforms, what does an agent-ready data platform actually look like?**

That experiment would make the article substantially stronger.

# 3. Apache Iceberg 1.11: The Data Catalog Is Turning Into a Query Planning Service

This is the sleeper pick.

Apache Iceberg 1.11 introduced a much more capable REST Catalog, including **remote scan planning**. Instead of every client fetching manifests and figuring out files itself, the catalog can perform planning and return the relevant scan tasks. [Apache Iceberg](https://iceberg.apache.org/blog/apache-iceberg-1.11.0-release/?utm_source=chatgpt.com)

That's a fascinating architectural change.
