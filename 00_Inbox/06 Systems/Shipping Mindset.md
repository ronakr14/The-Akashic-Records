# Shipping Mindset — Key Principles

## Summary
Compiled principles for shifting from thinking to shipping, killing over-engineering, and building artifacts that get used. Contains execution system rules, ROI filter, and career growth framework.

## Tags
#type/note #area/career #status/done

---

## Core Improvement Plan

### Shift from thinking → shipping
- Stop chasing "best approach"
- Start delivering working outputs fast

### Kill over-engineering early
- No frameworks, no abstractions, no scalability thinking
- Build the simplest thing that works

### Define "done" upfront
Every task must have:
- Clear output
- Clear scope
- Clear deadline

### Prioritize execution over optionality
- Pick one tool/model/approach quickly
- Commit and move forward

### Use before improving
- Don't optimize anything until:
  - You've used it multiple times
  - It proves real value

---

## Execution System

### Single-thread focus
- Only ONE active project at a time

### 2–2–2 cycle
- 2 hrs → decide
- 2 days → build
- 2 hrs → polish
- Then STOP

### No premature optimization
- No refactoring, no enhancements during build phase

### Ship artifacts only
- Output must be: runnable, usable, demo-able

### Weekly review
- Kill or commit
- If not useful → drop
- If useful → improve

## Top 3 High-ROI Projects

### 🥇 Data Pipeline Failure Debugger (9.5/10)
- Input: logs / error / SQL
- Output: root cause + suggested fix
- Why: Direct cost saving, happens DAILY, clear ROI

### 🥈 SQL Query Optimizer + Rewriter (9/10)
- Paste query → optimized version + cost estimation + index suggestions
- Why: Direct financial impact, easy to demo

### 🥉 "Saved Queries OS" (7.5/10)
- Central query store, auto-adapt to Postgres/BigQuery/etc.
- Target: Analytics teams in startups using Postgres + Metabase

## Career Growth Framework

### Target Identity
> "A tech lead who designs systems, drives decisions, and communicates impact clearly."

### Core Gaps to Fix
1. No end-to-end system thinking
2. Inconsistent communication
3. Low visibility
4. Passive in key moments

### Weekly Checklist
- [ ] 1 architecture/thinking note written
- [ ] Spoke in meetings (≥3 times total)
- [ ] Gave at least 1 recommendation
- [ ] Framed work in terms of impact (not effort)

### Speak with Recommendation Format
> "I recommend X because Y"

## Key Question

At end of each week:
> "Did I behave like a tech lead, or just a good engineer?"
